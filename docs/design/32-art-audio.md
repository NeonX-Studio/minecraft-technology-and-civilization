# 32 · 美术与音频规范

本章是所有自制视觉与声音资产的统一规范。它服务于 DR-29（写实 PBR，匹配 Patrix 类写实贴图包，只为自制内容出图，光影下表现良好）、DR-34（NeoForge + Sodium + Iris，默认 Complementary Reimagined）与 DA-07（2K/4K 母版，按 64x/128x/256x/512x 分级导出）。各模组章节的“内容清单”只给 ID 与用途；资产怎么做、做成什么规格、怎么验收，一律以本章为准。

---

## 1. 美术方向

### 1.1 一句话

> 像一张认真拍摄的纪录片截图：材料可信、光照真实、颜色克制；时代通过材料与工艺区分，而不是通过饱和度与特效区分。

### 1.2 原则

| 编号 | 原则 | 具体要求 | 反例 |
| --- | --- | --- | --- |
| AR-1 | 材料优先 | 每个方块先确定真实材料（岩性、木种、金属、织物），再画；不画“概念化”的方块 | 发光的“魔法矿石”出现在主世界 |
| AR-2 | 克制的颜色 | 主世界自制方块的平均饱和度（HSV S）不高于 0.45；高饱和只用于真实高饱和材料（孔雀石、辰砂、青金石、染料） | 卡通化的纯色矿点 |
| AR-3 | 可读性服从玩法 | 矿石必须在 8 格距离、正午与 Complementary 默认曝光下可辨；但辨识靠形态与纹理，不靠发光 | 为了可见性给矿石加自发光 |
| AR-4 | 时代靠工艺区分 | 石器：粗糙、手工不对称；青铜：铸造纹理与铜绿；铁器：锻打痕；中世纪：榫卯与铆钉；工业：铸铁、铆接钢板、黄铜；电气：电木、搪瓷、漆面；信息：注塑塑料、铝；太空：多层隔热、钛、复合材料 | 所有机器同一种灰色金属外壳 |
| AR-5 | 磨损讲故事 | Industry 的设备磨损（13 章）在贴图上有 3 级视觉状态：新、使用、待修 | 损坏只靠 GUI 数字显示 |
| AR-6 | 光影优先，原生可用 | 在 Complementary 下达到最佳；关闭光影时仍需清晰可辨、无明显错误 | 依赖光影才能看懂的方块 |
| AR-7 | 不复制第三方 | 只参考 Patrix 等写实包的风格（比例、色调、细节密度），绝不使用、描摹或再分发其资产 | 从第三方包裁剪纹理再调色 |
| AR-8 | Beyond 例外 | 只有 Beyond（21 章）的异界内容可以使用发光、非写实色彩与超自然形态，且必须在主世界“影响区”边界内 | 主世界原生生物带奇幻特效 |

### 1.3 风格参照系

风格对标是“写实 PBR 原版构图”：保留 Minecraft 的 1 格 = 1 方块构图与可平铺性，纹理细节密度接近 Patrix 类写实包。具体量化：

| 指标 | 目标值 | 测量方法 |
| --- | --- | --- |
| 平铺接缝 | 3×3 平铺无可见接缝 | 平铺测试图，100% 缩放目视 + 边缘像素差 ΔE < 3 |
| 宏观重复感 | 8×8 平铺时无明显“格子图案” | 每种自然方块提供 ≥ 2 个随机变体（见 3.6） |
| 平均亮度（albedo，sRGB） | 自然岩石 0.25-0.55，木材 0.20-0.50，雪 0.80-0.90 | 贴图平均值 |
| 法线强度 | 不超过 Patrix 类包同类材料的观感；粗糙石材 > 磨光石材 > 金属板 | 侧光对比图 |
| 光照下颜色 | Complementary 默认设置、正午，与参考照片色相差 ≤ 15° | 截图取色 |

### 1.4 主世界与原版内容

DR-29 规定只为自制内容出图。原版方块（草方块、原版石头、原版木头等）的外观取决于玩家自己的贴图包。整合包对此的处理：

1. 整合包默认不附带任何第三方贴图包。
2. 自制内容在“原版纹理 + 光影”下也必须协调：自制内容的色调范围按原版 16x 色板校准一次，按写实母版校准一次，取两者都可接受的中间值。
3. `README` 与首次启动提示中说明：推荐自行安装写实 PBR 贴图包以获得一致外观。
4. 因为 Wildlands 替换了主世界大部分岩石（10 章），原版石材在主世界中占比会显著下降；这降低了风格不一致的风险。

## 3. 方块与物品贴图

### 3.1 分辨率分级（DA-07）

| 档位 | 方块面尺寸 | 物品图标尺寸 | 用途 | 分发方式 |
| --- | --- | --- | --- | --- |
| 母版 | 2048 或 4096（材料扫描/雕刻） | 1024 | 制作源文件，不分发 | `art-src/`（仓库外或 Git LFS） |
| 512x | 512 | 256 | 发烧级 | 可选资源包 `tc-pbr-512x` |
| 256x | 256 | 128 | 高端 | 可选资源包 `tc-pbr-256x` |
| 128x | 128 | 64 | **整合包默认** | 资源包 `tc-pbr-128x`（整合包默认启用） |
| 64x | 64 | 32 | 基线 | **随模组 JAR 内置** |

规则：

1. 每个模组 JAR 只内置 64x 基线贴图（含 PBR 通道），保证不装任何资源包时也完整可用，且 JAR 体积可控。
2. 高分辨率档以资源包形式发布，一个资源包覆盖全部 18 个模组的命名空间。
3. 母版到各档位由导出脚本自动生成（3.8），禁止手工在低档位上单独修改，避免档位之间外观漂移。
4. 物品图标采用“2D 扁平图标”，尺寸为同档方块面的一半；工具和武器为 45° 斜向构图（与原版一致）。
5. 显存预算：默认 128x 档全部模组贴图（含 `_n`、`_s`）≤ 1.5 GB（02 第 8.2 节）。若汇总后超标，优先把装饰性方块降到 64x。

显存估算公式（用于导出脚本的预算检查）：

```text
vram_bytes ≈ Σ_textures ( w × h × 4 bytes × 3 maps × 1.33 mipmap )
128x 下单张方块面：128 × 128 × 4 × 3 × 1.33 ≈ 261 KB
预算 1.5 GB / 261 KB ≈ 6,000 张方块面等价
```

### 3.2 PBR 格式：LabPBR 1.3

所有方块与物品贴图使用 LabPBR 1.3 格式（Complementary Reimagined 在材质设置中启用资源包 PBR 时读取）。每张贴图三件套：

| 文件 | 通道 | 含义 | 制作规范 |
| --- | --- | --- | --- |
| `<name>.png` | RGB + A | 反照率 albedo（sRGB）；A 为透明度 | 不烘焙光照与阴影；AO 放 `_n` 的 B 通道 |
| `<name>_n.png` | R, G | 法线 X、Y（切线空间，OpenGL 约定 Y+ 向上） | Z 由着色器重建 |
| | B | 材质 AO（255 = 无遮蔽，0 = 完全遮蔽） | 只放材质微观遮蔽 |
| | A | 高度图（255 = 表面最高，越小越深；最小值用 1，不用 0） | 用于视差遮蔽 POM |
| `<name>_s.png` | R | 感知光滑度 smoothness（`roughness = (1 - R/255)^2`） | 粗糙石材 20-60；磨光大理石 180-220；新金属 200-240 |
| | G | 0-229：非金属 F0（线性，`F0 = G/255`）；230-254：预设金属；255：以 albedo 为 F0 的金属 | 非金属常用 F0 ≈ 0.04，即 G ≈ 10 |
| | B | 0-64：孔隙度 porosity（影响潮湿变暗）；65-255：次表面散射强度 | 树叶、冰、蜡、皮肤用 SSS |
| | A | 自发光 0-254（255 = 不发光） | 主世界自然方块必须为 255 |

LabPBR 预设金属 G 值（直接使用，不自定义 F0）：

| G 值 | 金属 | 本项目使用对象 |
| --- | --- | --- |
| 230 | 铁 Iron | 熟铁、铸铁、钢（钢用 230 并调高光滑度） |
| 231 | 金 Gold | 金锭、金饰 |
| 232 | 铝 Aluminum | 铝材、E9-E10 外壳 |
| 233 | 铬 Chrome | 镀铬件、不锈钢（近似） |
| 234 | 铜 Copper | 铜材、黄铜与青铜（青铜/黄铜用 255 + albedo 着色更准确，见下） |
| 235 | 铅 Lead | 铅材 |
| 236 | 铂 Platinum | 稀有催化剂（若出现） |
| 237 | 银 Silver | 银锭、银饰 |
| 255 | albedo 作 F0 | 青铜、黄铜、钛、镍、钨等无预设金属 |

### 3.4 方块贴图规则

1. **面一致**：同一方块的 6 面用同一材料参数；柱状方块（原木、柱）分 `_side` 与 `_end`。
2. **岩石四形态**：`<rock>`（自然面，随机旋转）、`<rock>_cobble`（碎石，块径 3-6 块/面）、`<rock>_bricks`（标准砖缝，砂浆缝宽 2 px@64x）、`polished_<rock>`（磨光，S 提高 60-140）。
3. **砂浆与缝**：砖缝在 `_n` 的高度通道比砖面低 25%，`_s` 的 porosity 比砖面高 15。
4. **透明与半透**：只用 cutout（树叶、栅栏、作物）或 translucent（玻璃、冰）；translucent 方块数量要少，因为 Sodium 下半透排序代价高。
5. **矿石**：见 3.7，围岩为底，矿物为叠加。
6. **作物与植物**：每个生长阶段一张；阶段数以 12 章为准。植物在 Iris 映射中标记为“摇摆植物”（第 6 节）。
7. **磨损三级**（AR-5）：可磨损设备提供 `<name>`、`<name>_worn`、`<name>_damaged` 三套贴图，由方块状态 `wear=0|1|2` 选择。
8. **季节变体**：叶片与草的季节色变由 Wildlands 的季节系统通过 `BlockColor` 着色实现，**不**为每季单独画贴图；只有“落叶后枯枝”“积雪”两种形态需要单独贴图。

### 3.5 连接纹理

1. 需要连接纹理的方块（玻璃窗、石砌墙面板、铁路道岔、管道外壳）使用 NeoForge 的模型数据 API（`ModelData` + 自定义 `BakedModel`）实现。
2. 必须在 Sodium 下验证：如果 Sodium 版本不支持该路径，则回退为“随机变体”而不是错误渲染。此回退由 `tcivilization-client.toml` 的 `connected_textures` 开关控制，默认 `auto`。
3. 不依赖第三方连接纹理模组。

### 3.6 随机变体

自然方块（岩石、土壤、沙、砾石、雪）至少提供 2 个变体，推荐 4 个；通过方块状态模型的 `weight` 与随机旋转（`y` 0/90/180/270）组合，得到至少 8 种视觉组合。

### 3.7 矿石合成管线

矿石数量是“围岩 × 矿物”的组合（ID 规范：`<host_rock>_<mineral>_ore`，见 README 5.2），手绘不可行。规则：

1. 每种围岩已有自身贴图（3.4）。
2. 每种矿物绘制一张**矿物叠加层**母版：`art-src/ore_overlays/<mineral>.png` + `_n` + `_s`，透明背景，只含矿物颗粒、细脉或结核。
3. 构建时由 Gradle 任务 `:tcwildlands:composeOreTextures` 按 10 章的合法组合表合成：
   - albedo：围岩 albedo 与叠加层按 alpha 混合；
   - `_n`：叠加区域的高度比围岩高 10-20%（颗粒凸出），法线重算；
   - `_s`：叠加区域的 S、F0 用矿物参数（如方铅矿 F0=230 金属光泽，孔雀石非金属 S 90）。
4. 只合成 10 章中允许出现的组合；非法组合不生成贴图，也不注册方块。
5. 合成脚本对每档位独立运行，避免先合成后缩放造成的颗粒糊化。

### 3.8 导出管线

```text
art-src/
  materials.json               材料参数库（3.3）
  blocks/<modid>/<name>/       每个方块一个文件夹
    albedo.(psd|exr|png)       2K/4K 母版
    normal.(exr|png)
    height.(exr|png)
    ao.(exr|png)
    roughness.(exr|png)
    meta.json                  材料引用、变体数、是否发光、Iris 类别
  items/<modid>/<name>/
  ore_overlays/<mineral>/

tools/art-export/              导出脚本（Python）
  export.py --tier 64|128|256|512 --mod <modid>|all
```

导出步骤：

1. 读取母版，按档位用 Lanczos 下采样；法线图在下采样后重新归一化。
2. 由 `roughness` 计算 `S = round(255 × (1 - sqrt(roughness)))`。
3. 打包 LabPBR 三件套（3.2）；高度最小值钳到 1。
4. 写入 `assets/<modid>/textures/block|item/`；64x 写入模组源码目录，其他档位写入资源包构建目录。
5. 生成 Iris 映射数据（第 6 节）与贴图清单。
6. 校验：尺寸是 2 的幂；`_n`/`_s` 与 albedo 尺寸一致；无未引用贴图；无缺失贴图；显存估算不超预算。

### 3.9 动画贴图

只用于确有运动的表面：流体、火、熔融金属、传送带表面、屏幕、指示灯。帧数 ≤ 32，帧时间 ≥ 2 tick；`.mcmeta` 中开启 `interpolate` 仅用于流体。机器运转主要通过方块实体渲染（BER）的部件运动表现，而不是动画贴图（符合 DR-20 可见实体过程）。

## 4. 模型与动画

### 4.1 方块模型

1. 工具：Blockbench；导出为原版 JSON 方块模型。
2. 单个方块模型 ≤ 64 个立方体元素；多方块机器拆成多个部件方块，每个部件 ≤ 64。
3. 运动部件（齿轮、轴、活塞、风车叶片、水车）由 BER 渲染，静态外壳用方块模型；BER 必须支持 Sodium 的视锥剔除，且在距离 > 48 格时停止动画，只画静态姿态。
4. 传动轴、齿轮的转速可视化与 13 章 RPM 严格对应：`rotation_deg_per_tick = RPM × 360 / 1200`。

### 4.2 实体模型与 LOD

| 类别 | LOD0（≤ 16 格） | LOD1（16-48 格） | LOD2（48-128 格） | 超出 128 格 |
| --- | --- | --- | --- | --- |
| NPC `tcivilization:person` | 完整模型 + 服装层 + 手持物 + 表情 | 合并服装层，无表情 | 单网格低模 + 基础色 | 不渲染（地图图标） |
| 动物（Ecology） | 完整骨骼 | 简化骨骼（≤ 8 骨） | 静态姿态 | 不渲染 |
| 车辆（Networks） | 完整 + 车轮/螺旋桨动画 | 车轮动画 | 静态 | 远景代理（火车可延伸到 256 格） |
| 火箭（Orbit） | 完整 | 完整 | 完整（发射时保持可见至 512 格） | 尾焰粒子 |

LOD 切换距离乘以客户端配置 `entity_lod_scale`（默认 1.0，范围 0.5-2.0）。500 名实体 NPC 时渲染 ≤ 3 ms/帧（02 第 8.2 节）。

### 4.3 NPC 外观系统

NPC 外观由“部件 + 调色板”组合，不为每个 NPC 画整张皮肤：

| 层 | 部件数（初始） | 由谁决定 |
| --- | --- | --- |
| 体型 | 6（身高 × 体格） | 随机 + 年龄 |
| 肤色 | 12 色带 | 文化起源地（Echoes 历史 / Nations 文化） |
| 发型 | 24 | 文化 + 随机 |
| 发色 | 10 | 文化 + 年龄 |
| 服装上身/下身 | 每时代 6-10 件 | 时代 + 职业 + 财富 |
| 头饰 | 每时代 4-6 件 | 职业 + 文化 |
| 职业道具 | 每职业 1-3 件 | 职业（15 章） |
| 制服/军装 | 每时代 2-4 件 | Frontiers / Nations |

规则：

1. 服装随所属文明的**时代**更新，不随单个 NPC。
2. 文化风格由“文化 ID”选择服饰纹样调色板；不同 AI 文明在同一时代外观可区分。
3. 外观纹理在客户端按“部件哈希”合成并缓存到图集，最多缓存 512 种组合；超出时按最近最少使用淘汰。
4. 不使用玩家皮肤格式，避免和原版玩家渲染耦合。

### 4.4 动画

1. 不使用第三方动画库（呼应“模组尽量自己写”）。实体动画使用原版关键帧动画定义（`AnimationDefinition` 风格的代码定义）或本项目在 tcivilization 中提供的轻量关键帧播放器 `TcAnimator`。
2. NPC 通用动作集：走、跑、坐、睡、搬运、挥锤、锯、挖、锄、播种、收割、驾驶、交谈、指路、战斗待机、攻击、受伤、欢呼、哀悼。每个职业复用通用动作并可追加 ≤ 3 个专属动作。
3. 动画混合只做两层：下半身移动 + 上半身动作。
4. 动画采样频率：LOD0 每帧；LOD1 每 2 帧；LOD2 不播放。

## 6. Iris 与 Complementary 兼容

### 6.1 问题

Iris 光影通过光影包内的 `block.properties`、`item.properties`、`entity.properties` 把方块/实体映射到着色器材质 ID（发光、摇摆植物、水、玻璃、金属等）。模组方块不在光影包映射表里时，会以默认材质渲染：植物不摇摆、玻璃没有折射、发光方块没有光晕。

### 6.2 方案

| 层 | 做法 | 说明 |
| --- | --- | --- |
| A：材质靠 LabPBR | 金属、光滑度、孔隙、SSS、自发光全部写进 `_s` | Complementary 启用资源包 PBR 后即可正确显示，不依赖映射 |
| B：映射清单生成 | 导出脚本从每个方块的 `meta.json` 读取 Iris 类别，生成 `tc_iris_mapping.properties` 片段 | 片段按 Complementary 的类别名组织 |
| C：本地合并工具 | 客户端命令 `/tcclient shadercompat apply <shaderpack>`：读取用户本机已安装光影包，生成**本地副本**并合并映射片段 | 不再分发第三方光影包，只修改用户本机副本 |
| D：上游提交 | 维护映射片段，向光影作者申请收录（若作者同意） | 长期方案 |

方块 `meta.json` 中的 Iris 类别（与 Complementary 常用类别对齐的项目内名称）：

| 类别 | 适用 | 示例 |
| --- | --- | --- |
| `solid` | 默认 | 岩石、砖 |
| `foliage_waving` | 草、作物、花 | `tccultivation:wheat` |
| `leaves_waving` | 树叶 | Wildlands 树种叶 |
| `vine_waving` | 藤蔓、悬挂植物 | |
| `water_like` | 自定义水体、盐水、污水 | Wildlands 河水变体 |
| `glass` | 玻璃、窗 | Industry 玻璃 |
| `ice` | 冰、海冰 | Wildlands 冰 |
| `emissive_full` | 熔融金属、炉膛、灯 | Industry 熔炉膛 |
| `emissive_partial` | 指示灯、屏幕 | 机器面板 |
| `metal` | 金属块（补充 LabPBR） | 钢板 |
| `snow` | 雪层 | |
| `lava_like` | 岩浆、熔岩管 | 下界深地 |

### 6.3 风险与限制

1. 光影包的类别 ID 在不同版本之间可能变化；合并工具必须先识别光影包版本，未知版本时只做 A 层，并提示用户。
2. 第三方光影包的再分发受其许可约束；本项目不分发修改后的光影包（00 第 7 节范围边界）。
3. 关闭光影时，`emissive_*` 方块需要原版光照等级（`lightEmission`）作为回退。

### 6.4 天空、天体与天气

1. 季节、纬度日长（10 章）只改变太阳轨迹与天气，**不**替换光影包的天空渲染。
2. 月球与火星维度（24 章）的天空：Iris 以维度 ID 选择光影的维度程序；没有专用程序时使用主世界程序。Orbit 提供 `DimensionSpecialEffects`：月球黑天空、无云、无雨；火星黄褐天空、尘暴雾效。
3. 下界深地（10 章）保留 `minecraft:the_nether` ID，因此光影包的下界程序继续生效（DA-09 的原因之一）。

## 7. 粒子与特效

| 原则 | 规则 |
| --- | --- |
| 少而准 | 每个机器同时 ≤ 4 个粒子发射器；远于 32 格不发射 |
| 物理可信 | 烟随风向（Wildlands 风场）偏移；蒸汽上升后扩散；火花受重力 |
| 污染可见 | 工业烟囱的烟浓度与 13 章排放量成正比：`particles_per_second = clamp(emission_kg_per_day / 50, 0.5, 12)` |

| 光影 | 发光粒子使用 emissive 渲染类型，便于光影识别 |

## 8. 音频

### 8.1 方向

> 声音是“地方感”的主要来源：同一片森林在春天和冬天、早晨和夜晚、远离文明和靠近工厂时，听起来都不同。

### 8.2 声音事件命名

```text
<modid>:<category>.<subject>[.<variant>]
例：tcwildlands:ambient.forest.temperate.day
    tcindustry:machine.steam_engine.run
    tcnetworks:vehicle.locomotive.whistle
    tcivilization:person.work.hammer
    tcatlas:ui.map.open
```

`category` 取值：`ambient`、`weather`、`block`、`item`、`machine`、`vehicle`、`entity`、`person`、`ui`、`music`、`event`。每个声音事件在 `sounds.json` 中登记，并在模组附录 A 以 `sound` 类型列出（只需列出类别级或重要事件，36 章汇总）。

### 8.3 技术规格

| 类型 | 格式 | 声道 | 采样率 | 响度目标 | 衰减 |
| --- | --- | --- | --- | --- | --- |
| 定位音效（方块、机器、实体） | OGG Vorbis q5 | 单声道 | 44.1 kHz | 峰值 -3 dBFS，短音效 -18 LUFS 起 | 线性，默认 16 格；大型机器 32-48 格 |
| 环境床（ambient bed） | OGG Vorbis q4，`stream: true` | 立体声 | 44.1 kHz | -24 LUFS | 非定位 |
| 环境点缀（鸟鸣、狼嚎） | OGG Vorbis q5 | 单声道 | 44.1 kHz | -20 LUFS | 定位，24-64 格 |
| 音乐 | OGG Vorbis q5，`stream: true` | 立体声 | 44.1 kHz | -18 LUFS 积分响度 | 非定位 |
| UI | OGG Vorbis q5 | 单声道 | 44.1 kHz | -20 LUFS | 非定位 |

每个重复使用的音效至少 3 个随机变体，并在 `sounds.json` 中设置 `pitch` 随机 ±5%（机器除外，机器音高由转速决定）。

### 8.4 声音通道预算

原版声音引擎同时可播放的通道数有限（普通通道远多于流式通道）。本项目自己的预算：

| 类别 | 同时上限 | 策略 |
| --- | --- | --- |
| 环境床 | 2（交叉淡入淡出时短暂 3） | 流式；只保留当前与下一个 |
| 音乐 | 1 | 流式 |
| 机器 | 16 | 按距离与音量排序，超出时远处静音 |
| 车辆 | 8 | 同上 |
| NPC 工作与人声 | 12 | 同上；聚落里用“人群环境床”代替逐个人声 |
| 环境点缀 | 8 | |
| 天气 | 4 | |
| 其他 | 剩余 | |

聚落人群：当 32 格内实体 NPC ≥ 12 时，用 `tcsettlements:ambient.crowd.<size>` 环境床替代个体闲聊音，个体只保留工作动作音。

### 8.5 环境声景系统（Soundscape）

环境床由客户端的 `SoundscapeManager`（tcivilization 提供框架，各模组注册声景层）选择，每 40 tick 评估一次：

```text
score(layer) = Σ weight_i × condition_i(player_context)
player_context = { biome, season, time_of_day, weather, altitude, depth,
                   indoor(enclosure ratio), nearby_settlement_size,
                   nearby_industry_noise, ecosystem_health, anomaly_level }
选择 score 最高的 1 个“基础层” + 至多 2 个“叠加层”
切换时交叉淡化 80 tick
```

| 来源模组 | 声景层示例 | 条件 |
| --- | --- | --- |
| Wildlands | 温带阔叶林、针叶林、草原、沙漠、苔原、海岸、山顶风、洞穴滴水、地下河、下界深地低频轰鸣 | 生物群系、海拔、深度 |
| Wildlands | 雨、雷暴、暴风雪、沙尘暴、季风雨 | 天气 |
| Ecology | 鸟类黎明合唱、夏夜虫鸣、蛙鸣、狼群 | 季节、时间、种群密度、生态健康 |
| Settlements | 村落日间、集市、城市交通、夜间城镇 | 聚落规模与时代 |
| Industry | 工业区低频噪声、蒸汽、电厂嗡鸣 | 13 章噪声场 |
| Orbit | 舱内设备嗡鸣、月面寂静（只有服装内声音）、火星风 | 维度 |
| Beyond | 异界低语、晶体共鸣 | 影响区强度 |

生态反馈：生态健康指数（11 章）越低，鸟鸣与虫鸣层权重越低。玩家能“听见”生态退化，这是支柱“世界有因果”的直接表现。

### 8.6 机器声音

1. 机器运转声音高与 13 章转速挂钩：`pitch = clamp(0.5 + RPM / 256, 0.5, 2.0)`。
2. 负载提高时叠加“吃力”层，音量与 `stress_ratio` 成正比。
3. 磨损等级 1、2 时叠加异响（摩擦、敲击）层：这是 AR-5 的听觉对应，玩家可以靠耳朵发现需要维护的设备。
4. 同类型机器在 8 格内 ≥ 4 台时合并为一个“机群”声源，避免通道耗尽。

### 8.7 NPC 声音

1. 不使用真实语言或 TTS；NPC 交谈是“无意义语音”（类似模拟人生式的拟声），按文化 ID 选择音色库与韵律。
2. 每个文化 ≥ 2 个音色（不按性别区分命名，只称“音色 A/B/C”）。
3. 工作声音（锤、锯、锄）与 4.4 的动作关键帧同步触发。

### 8.8 音乐

| 维度 | 规则 |
| --- | --- |
| 时代主题 | 每个时代 3-5 首；乐器随时代演进：骨笛与鼓（E0）→ 陶埙与竖琴（E2）→ 鲁特琴与管风琴（E4-E5）→ 管弦乐（E6）→ 加入电声（E7-E8）→ 合成器与氛围（E9-E10） |
| 情境 | 探索、聚落、夜晚、远征、战斗、太空；同一时代内按情境选曲 |
| 文化 | AI 文明境内时，使用该文明文化调式变奏（若有） |
| 频率 | 安静为主：每首结束后静默 3-8 分钟（随机），可配置 |
| 触发 | 时代跃迁、里程碑、首次登月等重大事件播放短乐句（stinger），8-20 秒 |
| 授权 | 只使用原创或明确可再分发授权的作品；授权信息登记在 `assets/<modid>/sounds/LICENSES.md` |

### 8.9 UI 声音

UI 声音随时代皮肤变化（翻页声 → 电木按键声 → 电子提示音），但每类 UI 动作的“时长与响度”保持一致，以免影响可用性。所有 UI 声音可在客户端设置中单独静音。

## 11. 验收标准

1. 不装任何资源包时，18 个模组的全部方块与物品有贴图，无紫黑缺失贴图（自动检查：资源重载日志无 missing texture）。
2. 默认 128x 资源包 + Complementary Reimagined（启用资源包 PBR）下：金属有反射、潮湿岩石变暗、植物有次表面散射、熔融金属发光。
3. 导出脚本对 64x/128x 档的检查全部通过（3.8 第 6 步）。
4. 默认档显存估算 ≤ 1.5 GB。
5. 矿石合成只生成合法组合；每个合法组合都有贴图。
6. 500 名实体 NPC 场景下实体渲染 ≤ 3 ms/帧（RTX 3070 级，02 第 8.2 节）。
7. 声景切换无突兀断音；32 格内 20 台机器同时运行时，声音通道占用不超过 8.4 预算。
8. 所有皮肤通过对比度检查；`colorblind_mode` 下分类图层可区分。
9. 资产授权：`LICENSES.md` 覆盖所有非原创资产；无第三方贴图包资产。
